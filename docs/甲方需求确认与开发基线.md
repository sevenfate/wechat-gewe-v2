## 1. 项目一句话

建设一个基于 GeWe 的私有化微信机器人管理系统：统一管理微信账号、联系人、已发现群和群成员，通过可热拔插插件扩展功能，并把插件权限精确控制到某个群或某个群成员；MaiBot 作为独立的拟人聊天服务，通过桥接插件接入本系统。

简单说：

- GeWe 负责“连上微信”。
- 本系统负责“管理账号、数据、插件、权限和可靠发送”。
- 普通插件负责“完成一项具体功能”。
- MaiBot 负责“像群友一样聊天和熟悉大家”。
- Task Agent 负责“协调多个工具，把一件复杂事情办完”。

## 2. 项目要解决的问题

本项目不是单纯做一个 GeWe API 操作面板，而是要解决以下实际问题：

1. 多个微信机器人缺少统一的登录、状态、消息和故障管理。
2. 联系人、群和群成员只存在于微信或 GeWe 返回结果中，无法稳定查询和管理。
3. 机器人功能容易写死，新增功能往往需要修改主程序并重启整套系统。
4. 插件不能让任何人随便使用，需要能限制到具体账号、群和群成员。
5. AI 可以聊天，也可以调用工具，但无论 AI 怎么判断，最终权限和发送权都必须由平台掌握。
6. 单个插件、MaiBot 或模型发生故障时，不能拖垮微信消息接收和其他插件。

## 3. 职责边界

| 组成部分 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| GeWe | 微信登录、消息收发、联系人和群相关 API | 本系统业务、插件权限、AI 决策 |
| 本系统核心 | 账号管理、消息可靠性、数据持久化、插件生命周期、权限、审计、发送队列 | MaiBot 的人格、记忆和聊天策略 |
| 普通插件 | 天气、搜索、提醒、查询等具体功能 | 绕过权限、直接使用 GeWe Token、直接向微信发送 |
| MaiBot | 拟人聊天、人格、记忆、群友画像、主动聊天时机和表达方式 | 平台权限判断、GeWe Token、最终微信发送 |
| MaiBot Connector | 在平台和 MaiBot 之间转发已授权消息、接收回复、报告健康状态 | 修改或管理 MaiBot 内部逻辑 |
| Tool Bridge | 让 MaiBot 以结构化方式申请调用平台插件 | 替 MaiBot 绕过 ACL 或审批 |
| Task Agent | 多步骤任务、工具协调、等待确认、失败恢复 | 模拟群友、维护 MaiBot 的人物记忆 |

平台是权限和发送的最终裁决者。MaiBot、Task Agent 和任何插件都不能直接获得 GeWe Token，也不能绕过平台自行向微信发送消息。

## 4. 核心需求

### 4.1 微信账号与消息

- 支持管理多个 GeWe Token 和微信账号，首期按 1 至 20 个账号设计。
- 支持扫码登录、在线状态、掉线提示、重新扫码和停用。
- 系统为每个 GeWe Token 展示一个公网回调地址，默认由甲方复制到 GeWe 后台“访问控制”中手动保存；平台接收验证并显示健康状态，但不会自动覆盖。
- 可选的平台代管模式只有在有权限管理员明确切换并点击设置后才调用 GeWe API；启动、扫码、重连和升级都不能擅自修改回调地址。
- 一个 Token 只能设置一个回调地址，该 Token 下所有微信账号共用入口，由平台按 `appId` 区分；需要不同回调时使用不同 Token。
- Webhook 收到消息后先可靠保存并快速响应，再异步交给插件或 AI，避免慢插件拖住回调。
- 重复回调不能造成重复回复或重复办事。
- 同一个微信账号的外发消息必须排队发送，避免并发调用 GeWe。
- 发送结果无法确认时标为“结果未知”，不盲目重发。
- 所有入站、权限判断、插件调用和外发结果可以沿同一条记录追踪。

当前代码已经具备 Connection、扫码/登录状态、Webhook、消息归一化与去重、目录同步、Outbox 和 Sender 的本地契约链路；尚未使用真实 GeWe Token、测试微信号和公网 HTTPS 回调完成端到端验收。

### 4.2 联系人、群和群成员

- 持久化联系人列表、已发现群列表和群成员列表。
- 保存昵称、群内昵称、角色、首次发现、最后同步和当前状态等必要信息。
- 通讯录同步、群消息和群变更事件共同补充本地数据。
- 群成员同步失败或结果疑似不完整时，不能误判大量成员已经退群。
- 成员退群后重新加入时，高风险旧授权默认不自动恢复。
- GeWe 不能保证返回微信中的全部历史群，因此后台统一使用“已发现群”，不宣传为“全部群”。

### 4.3 插件系统与热拔插

插件是系统扩展功能的主要方式。插件可以处理消息、提供命令，也可以把能力注册成供 AI 调用的 Tool。

首期要求支持完整的热拔插：

- 安装、配置、启用、停用、卸载插件时，不重启主系统，不中断微信回调和其他插件。
- 升级插件时先启动新版本并检查健康状态，再停止旧版本；升级失败继续保留旧版本。
- 停止或升级前不再接收新任务，对正在执行的任务进行排空或受控取消。
- 插件自己的 Runner 因依赖变化而重启是允许的，但不能影响核心服务和其他插件。
- 插件崩溃、死循环、超时或返回非法结果时，应被隔离、记录并熔断。
- 插件 ID、命令、Tool 和能力均未变化时可保留原运行 ACL；新版本新增任何 capability、Tool、命令或数据访问能力都默认拒绝，并重新批准 Deployment Grant。
- 插件数据通过平台提供的独立存储空间保存，卸载是否保留数据由管理员选择。

首期只运行甲方或项目方审核过的私有插件。独立进程主要解决故障隔离，不宣称可以安全运行任意恶意代码。

当前代码支持三个仓库内置插件的安装、Deployment/Revision、激活、停用、升级式切换和回滚，并使用独立进程与 activation epoch 隔离普通插件。任意私有包上传、完整卸载、签名信任库和恶意代码沙箱尚未实现。

### 4.4 权限管理

权限需要回答三个问题：谁、在什么地方、可以使用什么。

“谁”包括后台用户、私聊联系人、群成员、插件、MaiBot Connector 和系统任务；“什么地方”包括微信账号、私聊和群；“使用什么”包括插件、命令、Tool 和具体动作。

首期必须支持：

- 给整个微信账号设置插件默认权限。
- 给某个群单独允许或拒绝插件。
- 在同一个群里给某个成员设置例外权限。
- 给私聊联系人设置插件权限。
- 分别控制插件、插件命令和插件提供的 Tool。
- 支持“继承、允许、拒绝”三种状态，拒绝优先，无匹配时默认拒绝。
- 权限变更对后续消息和 Tool 调用立即生效。
- 后台能说明一次调用为什么被允许或拒绝。
- 所有授权、撤权、拒绝和审批都有审计记录。

对于 MaiBot Connector，至少要能分别控制：

- 是否允许接收这个群或成员的消息。
- 是否允许在这个群回复。
- 是否允许在群里主动发起聊天。
- 是否允许响应这个成员的请求并调用 Tool。

未授权成员的消息默认不转发给 MaiBot，也不能借其他人的身份调用 Tool。群里其他人主动引用或转述该成员内容时，平台无法保证从自然语言中完全清除间接信息，这不作为成员级隐私隔离承诺。

当前运行 ACL 已覆盖账号、私聊、群、群成员与插件/命令/Tool/capability，并把判定结果持久化；甲方测试群中的真实允许/拒绝矩阵仍待 UAT。

## 5. MaiBot 接入方式

### 5.1 MaiBot 是独立黑盒

MaiBot 独立部署和运行。本系统不开发、不复制也不管理以下内容：

- MaiBot 的人格、说话方式和主动聊天策略。
- MaiBot 如何形成、检索或删除记忆。
- 群友画像、群内梗、关系判断和熟悉程度。
- MaiBot 内部模型、提示词、数据库和管理页面。

本系统只管理 MaiBot Connector 的配置、权限、在线状态、输入、输出和调用记录。停用 Connector 或撤销权限只保证停止后续转发；MaiBot 过去已经保存的数据，需要在 MaiBot 自己的系统中处理。

“像真人”属于 MaiBot 的产品效果，不作为本平台自研 AI 的验收项。本平台对 MaiBot 的验收重点是：该转发的消息能转发，不该转发的消息被拦截，回复和 Tool 调用都不能绕过权限。

### 5.2 普通聊天流程

```text
微信消息
  -> GeWe 回调
  -> 本系统保存、去重并识别账号/群/成员
  -> 检查这个群和成员是否允许使用 MaiBot Connector
  -> 有权限才转发给独立运行的 MaiBot
  -> MaiBot 自己判断是否回复、何时回复、说什么
  -> Connector 把回复作为受控动作交回平台
  -> 平台再次检查回复或主动发送权限
  -> 进入发送队列并通过 GeWe 发回微信
```

MaiBot 不需要等别人 `@` 才能参与聊天。只要群被授权，它可以接收普通聊天，由它自己决定保持安静、自然插话或主动发起话题。MVP 平台负责权限、全局发送限速和紧急停用；按群安静时段、次数窗口等细化运营策略进入 V1。平台不代替 MaiBot 做聊天决策。

### 5.3 MaiBot 调用平台插件

```text
群友用自然语言提出需求
  -> MaiBot 判断需要使用某个 Tool
  -> Tool Bridge 提交结构化调用请求
  -> 平台根据微信账号、群、真实成员和来源消息检查权限
  -> 允许后调用对应插件
  -> 插件结果返回 MaiBot
  -> MaiBot 组织成自然回复
  -> 回复仍经过平台权限和发送队列
```

有明确消息来源的请求必须关联平台签发的账号、会话、真实发言人和来源消息上下文，并带上 Tool、参数和唯一调用 ID，用来鉴权、审计和防止重复执行。没有明确发言人的主动请求只使用 Connector 自己的低权限身份。

平台会在 Tool 提供给 MaiBot 前过滤一次，在真正执行时再检查一次。MaiBot 主动发起而没有明确请求人的操作，使用 Connector 自己的低权限身份，不能借用最近一位群友的权限。

首期只向 MaiBot 开放天气、搜索、通讯录查询等低风险只读 Tool。提醒、写入和群管理等有副作用的能力在后续按风险逐步开放。

Connector 断线时只在较短有效期内保留有限积压，并按会话顺序重投。每次重投前都重新检查最新权限；离线期间已撤权或已超过有效期的旧聊天不会在重连后补给 MaiBot，MaiBot 对过期上下文返回的迟到回复也不会发到微信，避免突然回复很久以前的话题。

当前 Connector 已实现受管 WebSocket、ACK、重连退避、TTL、积压上限、幂等、fencing、回复目标校验和主动消息专用权限；尚未锁定真实 MaiBot 版本并完成端到端联调。MaiBot Tool Bridge 仍是后续阶段，当前不能宣称 MaiBot 已可安全调用天气或其他平台插件。

## 6. Task Agent 是什么

Task Agent 可以理解为“复杂任务执行器”，不是另一个拟人聊天机器人。

例如群友说：

> 把刚才大家提到的聚餐地点整理出来，查一下周六天气，给出三个方案，确认后再创建提醒。

普通插件通常只能完成其中一项。Task Agent 会把事情拆成几步，调用多个 Tool，等待用户确认，再继续完成后面的步骤。系统重启后，它仍能知道上次做到哪里，也不会把已经执行过的操作随便再做一次。

首期 Task Agent 只包含：

- 一个任务包含多个步骤和多个 Tool 调用。
- 任务状态和关键步骤持久化。
- 需要确认时暂停，得到合法答复后继续。
- 服务重启或模型中断后从安全位置恢复。
- 对步骤数、运行时间、Tool 次数、Token 和费用设置上限。
- 所有动作继续受群、成员、插件、Tool 和高风险策略限制。

Task Agent 不负责 MaiBot 的人格、长期记忆和群聊参与感。MaiBot 可以发起一个复杂任务，Task Agent 完成后再把结果交给 MaiBot 自然地告诉群友。

当前已经完成 Task Agent 的持久模型、状态服务、管理 API 和后台工作台，包括 Definition/Version/Session/Run、幂等、单活动 Run、追加事件、等待指定用户回答和人工状态控制。它还没有接入模型 Worker、Tool Broker、通用审批、预算或微信/MaiBot 任务入口，所以现在可以管理和检查任务状态，但还不能让模型自动把上述示例完整办完。

管理端身份不能由表单冒充：发布者和 Session 发起人由当前登录管理员自动确定。普通用户本人回答将来必须从可信微信/MaiBot 入口绑定真实身份；当前后台只提供独立权限控制的“管理员代答”，必须填写代答原因，并记录真实管理员和审计。状态页默认展示 Event、Inbox、Question 各自最近 100 条，若还有更早记录会明确提示截断。

## 7. 版本范围

本章描述交付目标，不等同于当前完成清单。当前事实以[《当前实现状态与验收边界》](./当前实现状态与验收边界.md)为准。

### 7.1 MVP：首个可投入测试群使用的完整版本

- GeWe Token 和 1 至 20 个微信账号管理。
- GeWe 回调地址默认手动管理，支持复制地址、验证和健康监控；平台代管为显式可选模式。
- 扫码登录、在线状态、Webhook、消息保存、去重和可靠发送。
- 文本私聊、群聊、`@` 和引用文本。
- 联系人、已发现群和群成员持久化与同步。
- 插件安装、配置、启停、卸载、升级、回滚和故障隔离。
- 插件命令、事件处理和 Tool 注册。
- 后台角色权限，以及账号、群、成员、插件、命令和 Tool 运行权限。
- MaiBot Connector，支持普通群聊转发、回复和受控主动聊天。
- Tool Bridge，首期开放低风险只读 Tool。
- 基础 Task Agent：多步骤、持久状态、审批、恢复、预算和审计。
- 受信任的内置只读 Skill：版本固定、按需加载，不能扩大 Tool 或权限。
- 管理后台、Trace、基础告警、备份和恢复验证。
- 会话人工接管：接管后暂停 MaiBot 转发和自动回复，人工回复仍经权限、发送队列和审计；解除后默认不补发接管期间的旧消息。
- Echo/诊断示例插件，以及一个天气或信息查询类真实插件。

### 7.2 V1：MVP 稳定后的增强版本

- 图片、语音、视频、文件等完整媒体收发。
- 插件测试群灰度、签名信任库、容器级资源和网络限制。
- 更多 MaiBot 版本适配、健康诊断和高级恢复策略；基础断线重连、短期积压 TTL 与 fencing 已在 MVP 提供。
- 在审批下开放提醒、写入数据等可撤销 Tool。
- 定时任务、完整 Task Agent Skill 安装/发布管理、知识库、多模型和一次性 Subagent。
- 按群安静时段、次数窗口和更细的 Connector 运营限额。
- 更完整的监控、增量备份、外部告警和数据导出/删除。

### 7.3 当前明确不做

- 自研或改造 MaiBot 的拟人、人格、记忆和群友画像。
- 公共多租户 SaaS、注册计费和公共插件市场。
- 任意来源插件的在线安装和“绝对安全沙盒”承诺。
- 朋友圈、视频号、自动批量加好友和营销群发。
- 无需审批的拉人、踢人、改管理员、解散群和跨群批量发送。
- 普通插件或 Agent 任意使用宿主 Shell、浏览器和文件系统。
- 完整 MCP、长期多 Agent 团队、复杂任务 DAG 和自动发布插件代码。

## 8. 甲方验收场景

MVP 至少通过以下甲方可观察的场景：

1. **账号、回调与数据**：复制系统地址到 GeWe 后台完成手动设置和验证；重启或重连不会覆盖；同一 Token 下两个测试微信号完成扫码、正确路由、文本收发和目录同步。
2. **权限**：在同一测试群里，指定成员可以使用天气命令，另一成员被拒绝；后台能说明两次结果分别命中了哪条规则。
3. **热拔插**：天气插件连续启用、停用、升级和回滚，核心系统、微信回调和其他插件不中断，也不出现重复回复。
4. **故障隔离**：让一个测试插件超时或崩溃，其他插件仍能工作，消息不会丢失，后台可以看到故障原因。
5. **MaiBot 普通聊天**：测试群无需 `@` 机器人，已授权消息可以送达 MaiBot，MaiBot 回复通过平台发回；未授权群或成员消息不会直接转发。
6. **MaiBot 主动聊天**：只在开启主动聊天权限的测试群允许 MaiBot 主动发言；关闭权限后立即不能继续主动发送。
7. **Tool Bridge**：有权限成员自然语言请求天气，MaiBot 能调用天气 Tool；无权限成员发出相同请求时，Tool 不执行且拒绝有审计记录。
8. **Task Agent**：运行一个包含查询、整理、等待确认和创建测试结果的多步骤任务；等待期间重启服务，恢复后只继续一次。
9. **消息可靠性**：同一真实回调重复发送十次，只产生一份业务结果；外发超时且结果未知时不会自动重复发送。
10. **可追踪**：从一条微信消息可以查到消息接收、权限判断、Connector/插件/Task Agent、Tool、发送队列和最终结果。
11. **人工接管**：Operator 接管测试群后，MaiBot 不再收到新消息且不再自动回复；人工消息正常发送，解除接管后不补发接管期间的旧消息。

MaiBot 是否足够像真人、是否记得某位群友，由甲方在 MaiBot 自身环境中评价，不作为本平台代码质量或完成状态的判断依据。
