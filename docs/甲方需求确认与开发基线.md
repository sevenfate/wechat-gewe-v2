## 1. 项目目标

交付一套可私有部署、可管理多个微信账号、支持普通插件和细粒度权限、具备可靠发送与审计能力的微信机器人平台。

核心价值：

- 管理 GeWe Connection、微信账号和回调。
- 保存联系人、群、群成员和消息 Trace。
- 通过独立进程运行普通插件，支持启停、升级和回滚。
- 按账号、群、成员、插件和命令控制运行权限。
- 所有外发消息经过持久 Outbox、限速、重试和发送前重新鉴权。
- 为后续 Task Agent 提供持久状态、审批和受控执行基础。

## 2. 职责边界

| 组件 | 职责 |
| --- | --- |
| GeWe | 连接微信，提供扫码、账号状态、通讯录、回调和发送 API |
| 平台核心 | 身份、权限、数据、插件生命周期、消息分发、Outbox 和审计 |
| 普通插件 | Echo、天气、查询、提醒等确定性能力，只返回受控 Action |
| Task Agent | 后续处理多步骤、等待确认、失败恢复的复杂任务 |

平台拥有 GeWe Token 和最终发送权。普通插件与 Task Agent 不得直接连接核心数据库或绕过 Outbox 调用 GeWe。

## 3. MVP 范围

### 3.1 微信核心

- 管理 GeWe Token 和 1 至 20 个微信账号。
- 默认手动设置回调地址，平台代管必须显式启用。
- 支持扫码登录、在线检查、重连和停用。
- 接收并保存文本回调，按 `appid + newMsgId` 去重。
- 支持文本私聊、群聊、`@` 和引用文本。
- 保存联系人、已发现群和群成员。
- 支持消息 Trace 和原始回调审计。

### 3.2 插件与权限

- 安装仓库内审核过的内置插件。
- 创建 Deployment 和不可变 Revision。
- 支持不停核心服务的启用、停用、升级和回滚。
- 单个插件异常不能拖垮 Webhook 和其他插件。
- 支持账号、私聊联系人、群和群成员作用域。
- 支持插件、命令、Tool 和 capability 资源权限。
- 默认拒绝，显式拒绝优先，并记录命中规则。

### 3.3 可靠发送

- 所有发送进入持久 Outbox。
- 同一账号严格串行并执行限速。
- 可确认失败按策略重试；结果未知不自动重发。
- 发送前重新检查账号、插件 Revision、目标和最新权限。
- 支持取消和人工确认成功/失败。

### 3.4 管理后台

- Owner 初始化、登录、退出和后台用户/角色管理。
- Connection、账号、通讯录、群成员、插件和权限配置。
- 消息 Trace、Outbox 和审计查询。
- Task Agent 持久控制台作为后续执行能力的管理入口。

### 3.5 Task Agent 后续闭环

Task Agent 的 MVP 完成条件包括：

- 模型 Worker 和受控 Tool 调用。
- 多步骤执行、持久检查点和重启恢复。
- 等待指定用户回答与管理员代答审计。
- 通用审批、预算、次数和时间限制。
- 明确的后台或微信命令入口。

当前只完成持久控制面，不把人工操作状态机表述为自动执行能力。

## 4. 当前明确不做

- 公共多租户 SaaS、注册计费和公共插件市场。
- 任意来源插件的在线安装和绝对安全沙箱承诺。
- 朋友圈、视频号、自动批量加好友和营销群发。
- 无审批的拉人、踢人、改管理员、解散群和跨群群发。
- 普通插件或 Agent 任意使用宿主 Shell、浏览器和文件系统。
- 完整 MCP、长期多 Agent 团队、复杂 DAG 和自动发布插件代码。

## 5. 验收场景

1. 两个测试微信号完成扫码、正确路由、文本收发和目录同步。
2. 同一测试群里，指定成员可以使用天气命令，另一成员被拒绝，后台能解释命中规则。
3. 天气插件连续启用、停用、升级和回滚，其他链路不中断且不重复回复。
4. 一个测试插件超时或崩溃时，其他插件继续工作，后台可查看失败原因。
5. 同一真实回调重复发送十次，只产生一份业务结果。
6. 外发超时且结果未知时不自动重发，可人工对账。
7. 从一条微信消息可以追踪接收、权限、插件、Outbox 和最终结果。
8. PostgreSQL 多 Worker 下不会重复领取事件和发送任务。
9. 数据库备份能够在隔离环境恢复并重新启动平台。
10. Task Agent 完成查询、整理、等待确认和恢复执行后，才计入自动任务验收。
