## 1. 产品边界

本项目交付一套私有部署的微信机器人管理平台：

- GeWe 负责微信连接和微信 API。
- 本系统负责账号、Webhook、联系人、群与群成员、插件、运行权限、可靠发送和审计。
- 普通插件负责 Echo、天气、查询、提醒等确定性能力。
- Task Agent 后续负责多步骤任务、等待确认和失败恢复，不参与普通插件命令链路。

平台始终是权限和微信发送的最终裁决者。插件和未来 Task Agent 都不能直接获得 GeWe Token，也不能绕过 ACL 和 Outbox 直接发送微信。

## 3. 已确认的真实链路

2026-09-01 晚间完成真实微信 `/echo` 文本联调，用户提供的结果显示发送 `/echo 联调测试3` 后收到了 `联调测试3` 回复。

该证据确认了以下纵向路径：

```text
真实微信消息
  -> GeWe 回调
  -> Webhook 持久化与标准化
  -> Event Worker
  -> Echo 命令与插件 Runner
  -> reply.text Action
  -> Outbox
  -> GeWe 文本发送
  -> 微信收到回复
```

当前证据只用于确认文本主路径已经打通，不自动证明以下场景：

- 群聊、`@`、引用文本和多个账号路由。
- 重复回调十次仍只产生一次业务结果。
- 发送超时后进入 `UNKNOWN` 且不重复发送。
- 权限撤销后排队消息在发送前被拒绝。
- 服务或数据库重启后的租约恢复。
- PostgreSQL 多 Worker 并发语义。

## 4. 当前架构

```text
微信
  <-> GeWe API / Webhook
  <-> FastAPI 核心
       |- Connection、账号与加密凭据
       |- Webhook Inbox、标准消息与 Trace
       |- 联系人、群和群成员
       |- ACL / Capability 判定与审计
       |- Plugin Catalog / Deployment / Revision
       |- Event Worker -> 独立插件 Runner
       |- Outbox -> 账号级 Sender -> GeWe
       `- Task Agent 持久控制面（尚无执行 Worker）

Vue 管理后台 <-> `/api/auth` 与 `/api/v1`
PostgreSQL       <-> 生产持久化与并发语义
```

核心规则：

1. Webhook 先持久化并快速返回，再异步处理。
2. 插件只返回受控 Action，不直接调用 GeWe。
3. 所有发送先进入 Outbox，并在真正发送前重新检查最新权限。
4. 插件 Revision 使用 activation epoch fencing，旧实例结果不能冒充新 Revision。
5. SQLite 只用于本地开发和单元测试；生产及锁语义验收必须使用 PostgreSQL。

## 6. 已知限制

- GeWe 和非官方微信接入存在掉线、接口变化和账号限制风险。
- 如果上游不提供可靠签名，高熵回调路径和 TLS 只能降低风险，不能证明请求来源。
- 插件子进程是故障隔离，不是任意恶意 Python 代码的安全沙箱。
- AI 输出不可信；未来 Task Agent 的写操作必须经过结构化校验、权限、必要审批和审计。
- 历史外部聊天桥接及其调用账本已从产品范围移除。迁移 `c3a9f1e2d4b6` 会永久删除对应数据，应用前必须备份。
