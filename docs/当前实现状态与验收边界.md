## 1. 甲方需求与产品边界

本项目最终要形成一套私有部署的微信机器人管理平台：

- GeWe 负责连接微信和提供微信 API。
- 本系统负责账号、Webhook、联系人、已发现群、群成员、插件、权限、可靠发送和审计。
- 普通插件负责天气、查询、提醒等确定性功能。
- MaiBot 作为独立服务负责拟人聊天、人格、记忆、群友画像和主动参与群聊。
- Task Agent 负责多步骤办事、等待确认、失败恢复和受控 Tool 调用，不负责扮演群友。

平台始终是权限和微信发送的最终裁决者。MaiBot、Task Agent 和插件都不能直接获得 GeWe Token，也不能绕过 ACL 和 Outbox 直接向微信发送。

当前授权只覆盖本地开发、自动化测试和构建，不自动包含：

- 生产服务器部署、域名或数据库变更。
- 使用正式微信号、真实群聊或真实 GeWe Token。
- 真实 MaiBot、模型 Provider 或外部 Tool 联调。
- 拉人、踢人、修改群管理、批量发送等高风险动作。

## 3. 当前系统架构

```text
微信
  <-> GeWe API / Webhook
  <-> FastAPI 核心
       |- Connection、账号与加密凭据
       |- Inbox、标准消息与 Trace
       |- 联系人、已发现群、群成员
       |- ACL / Capability 判定与审计
       |- Plugin Catalog / Deployment / Revision
       |- Event Worker -> 独立插件 Runner
       |- Outbox -> 账号级 Sender -> GeWe
       |- MaiBot Managed Runtime <-> 独立 MaiBot
       `- Task Agent 管理 API / 持久状态控制面（尚未接执行 Worker）

Vue 管理后台 <-> `/api/auth` 与 `/api/v1` 管理 API
PostgreSQL       <-> 生产持久化与并发语义
```

核心所有权规则：

1. Webhook 先持久化并快速返回，再异步处理。
2. 插件和外部 Agent 只返回受控 Action，不直接调用 GeWe。
3. 所有发送先进入 Outbox，并在真正发送前重新检查最新权限。
4. 插件 Revision 和 MaiBot 连接使用 activation epoch 做 fencing，旧运行实例不能继续产生有效动作。
5. SQLite 仅用于本地快速开发和单元测试；生产及并发/锁语义验收必须使用 PostgreSQL。
6. MVP 只允许一个 Workspace。数据库唯一约束、Connection 创建和应用启动均拒绝第二个 Workspace；后台角色权限在该唯一 Workspace 内全局生效，不把前端筛选当作安全边界。

## 4. GeWe 回调操作边界

默认流程是手动回调：

1. 管理员在后台创建 GeWe Connection。
2. 平台生成并展示形如 `https://你的域名/webhooks/gewe/<随机密钥>` 的回调地址。
3. 甲方把该地址复制到 GeWe 后台“访问控制”并手动保存。
4. GeWe 发出验证或业务回调后，平台更新最近回调时间和健康状态。

创建 Connection 时默认使用 `MANUAL` 模式。启动服务、扫码、重连、升级和恢复运行实例都不会自动调用 GeWe 的设置回调接口。

只有管理员先明确切换为 `PLATFORM_MANAGED`，再点击应用回调，后端才允许调用 GeWe `setCallback`。这是一项显式管理动作，不是系统自愈动作。

真实使用还要求：公网 HTTPS、反向代理正确转发原始请求体、合理限流，以及甲方在 GeWe 后台完成配置。平台的高熵路径只能降低误投和扫描风险；如果 GeWe 不提供可验证签名，它不能证明请求一定来自 GeWe。

## 5. 插件热拔插与 ACL

当前“热拔插”已经支持的范围：

- 安装三个受信任内置插件。
- 为插件创建 Deployment 和不可变 Revision。
- 新建配置 Revision 后激活，或选择旧 Revision 回滚。
- 启用、停用和重启恢复时不重启 FastAPI 核心。
- 普通插件使用独立 Python 子进程；单个 Runner 停止不应带倒核心进程。
- 激活切换使用 epoch fencing，旧 Worker 的迟到结果不能冒充新 Revision。
- Manifest 声明事件、命令、Tool、配置 Schema 和 capabilities；Deployment grant 不能超出 Manifest。

当前尚不能把任意来源的压缩包上传后在线安装，也没有完整卸载、签名信任库、依赖安装或恶意代码沙箱。现阶段只能运行仓库内、经项目方审核的内置插件。

运行权限按以下上下文判定：

```text
真实 Principal
  + 微信账号
  + 私聊/群作用域
  + 群成员及 membership epoch
  + 插件/命令/Tool/capability
  + 当前时间与策略版本
  -> ALLOW / ASK / DENY
```

同一精确度下 `DENY` 优先；无匹配默认拒绝。群成员退群再加入会产生新的 membership epoch，旧的成员授权不会自动复活。权限决定会持久化，Outbox 发送前还会再次鉴权，因此排队期间撤权可以阻止尚未发送的动作。

## 6. MaiBot 独立桥接与可信 Tool 边界

MaiBot 不嵌入 FastAPI 主进程，也不作为本系统数据库的一部分。`builtin.maibot-connector` 是受管插件标识，核心为它启动专用 WebSocket Runtime。

当前 Connector 已实现：

- 仅把通过工作区、Deployment scope、Revision grant 和运行 ACL 的消息送给 MaiBot。
- API key 和连接配置按 Secret 处理；日志和管理 API 不回显真实密钥。
- 待发消息持久化，具有 TTL、积压上限、ACK 后确认、断线重连和退避。
- 重投沿用同一传输标识，重复 ACK 或重复回复不产生重复微信动作。
- MaiBot 回复必须绑定平台已发出的来源消息；不能由外部报文任意指定目标群。
- 主动消息默认关闭。启用后仍必须同时满足配置开关、Revision 专用 grant、Connector service principal 在目标会话上的 ACL，并最终进入 Outbox。
- 停用、回滚或重新激活后，旧 activation epoch 的连接和回复失效。

可信 Tool 边界尚未完成。最终 Tool Bridge 必须做到：

1. 平台签发来源账号、会话、真实成员和来源消息上下文，不能信任 MaiBot 自报身份。
2. 只把当前身份可见的低风险 Tool 暴露给 MaiBot。
3. 真正执行时再次检查参数绑定、ACL、Deployment grant、幂等键和审批状态。
4. Tool 结果回给 MaiBot 组织自然语言，最终回复仍经过 Outbox。
5. MaiBot 主动发起且没有真实请求人的任务只能使用 Connector 自身的低权限身份。

在上述闭环完成前，不能宣称 MaiBot 已能安全调用天气或其他平台插件。

## 7. Task Agent 当前控制面与后续阶段

Task Agent 当前不是完整可用的自动办事 Agent，但已经从纯数据底座推进到受权限保护、可由管理员操作和观察的持久控制面：

- Agent Definition 与不可变 Version。
- 按工作区、版本、请求 Principal 和任务作用域隔离的 Session。
- 带幂等键的 Run，同一 Session 只允许一个活动 Run。
- `QUEUED`、`RUNNING`、`WAITING_APPROVAL`、`WAITING_USER`、`PAUSED` 及终态转换约束。
- 追加式 Session Inbox 和 Event 序列。
- 只允许指定 Principal、在有效期内回答一次的 Pending Question。
- 持久 JSON 规范化、大小限制，并拒绝持久化敏感推理字段。
- `/api/v1/task-agent` 管理 API 和后台工作台，可创建 Definition、发布 Version、创建 Session/Run、执行合法状态转换、创建待答问题并查看状态。
- `agent.read`、`agent.write`、`agent.run`、`agent.question.override` 四项独立后台权限；读写接口同时受登录、单工作区约束，写接口受 CSRF 保护。
- `GET /api/v1/task-agent/context` 由后端返回唯一 Workspace，前端不提供 Workspace 自选或手工切换，也不依赖 Connection 权限推断 Workspace。
- 发布 Version 和创建 Session 时，Publisher/Requester 均由当前登录管理员映射为 `ADMIN_USER Principal`，请求体不能指定其他身份。
- 管理端不提供可提交任意 `principal_id` 的普通 `/answer`。管理员代答只能使用 `POST /questions/{id}/override-answer`，要求独立权限和必填原因，并记录真实管理员、`ADMIN_OVERRIDE` 事件及审计。
- 所有 Task Agent 管理写操作的成功及领域失败均有审计；状态变更使用 Workspace 限定的锁定读取和最新数据库状态，终态 Run 不能被陈旧 ORM 状态复活。
- Session 状态默认分别返回最近 100 条 Inbox、Event 和 Question，`history_limit` 可设为 `1..200`；三个 `*_has_more` 明确表示更早历史被截断，工作台会显示提示。
- `analysis`、`thinking`、`reasoning*`、`chainOfThought` 等常见 snake_case、kebab-case、camelCase 私有推理字段在写入时拒绝，读取旧记录时递归过滤。

当前管理 API 的权限边界：

| 权限 | 可执行范围 |
| --- | --- |
| `agent.read` | 读取 Workspace Context、Definition/Version、Session/Run 和最近状态历史 |
| `agent.write` | 创建 Definition、发布不可变 Version |
| `agent.run` | 创建 Session/Run、执行状态转换、为运行中的 Run 创建待答问题 |
| `agent.question.override` | 管理员代答待答问题；不能伪装成被指定的普通回答者 |

普通用户本人回答所需的服务层校验已经存在，但面向微信、MaiBot 或其他可信运行时的身份绑定入口尚未开放；在该入口完成前，不能把管理员代答当作真实用户回答验收。

下一阶段按以下顺序完成：

1. 接入统一只读 Tool Broker，先开放 Echo、天气，并落实 Agent Version 精确白名单、执行时 ACL/Deployment/Revision/epoch 二次检查、结果 Schema、幂等和迟到结果拒绝。
2. 接入可替换模型 Provider 与 LangGraph 或等价执行 Worker，但不把第三方 Runtime 当作权限边界。
3. 补齐通用审批、预算、成本和可恢复检查点，形成真正的多步骤执行闭环。
4. 提供可信的普通用户回答、明确微信命令和 MaiBot Tool Bridge 入口；普通群聊仍由 MaiBot 负责，不由 Task Agent 抢答。
5. 在真实模型凭据、真实 PostgreSQL 和测试群中完成等待确认、服务重启恢复、幂等 Tool 与费用上限 UAT。

## 8. 本地安装与运行

### 8.1 前置环境

- Python `3.12`
- `uv`
- Node.js 与 `pnpm 11`
- PostgreSQL `16+`（生产和并发验收必需；本地快速开发可暂用 SQLite）

### 8.2 快速开发模式

未创建根目录 `.env` 时，development 默认使用本地 SQLite，并在 `.data/master.key` 首次生成开发密钥：

```powershell
cd backend
uv sync --all-groups
uv run alembic upgrade head
uv run uvicorn wechat_bot.main:app --reload
```

另开终端启动前端：

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

默认地址：

- 管理后台：`http://127.0.0.1:5173`
- 后端 OpenAPI：`http://127.0.0.1:8000/api/docs`（仅本地环境开放）

首次创建 Owner 前，应临时设置长度不少于 32 字符的 `WECHAT_BOT_AUTH_BOOTSTRAP_TOKEN`，在 `/bootstrap` 完成创建后立即从环境中移除并重启服务。

### 8.3 PostgreSQL 模式

```powershell
Copy-Item .env.example .env
# 修改 .env 中的数据库密码、WECHAT_BOT_MASTER_KEY、Bootstrap Token 和公网地址
docker compose up -d postgres
cd backend
uv sync --all-groups
uv run alembic upgrade head
uv run uvicorn wechat_bot.main:app
```

Staging/Production 强制使用 PostgreSQL、有效 Fernet 主密钥和 HTTPS `WECHAT_BOT_PUBLIC_BASE_URL`。不要把 `.env`、Token、密钥或数据库文件提交到 Git。

## 11. 安全与已知限制

- GeWe 和非官方微信接入存在无法由本系统消除的掉线、接口变化和账号限制风险。
- Webhook 没有可靠上游签名时，高熵路径、TLS、限流和未知账号隔离只能降低风险，不能提供密码学来源证明。
- 插件子进程提供故障隔离，不是对任意恶意 Python 代码的安全沙箱。
- MaiBot 已接收的数据及其记忆由 MaiBot 自己管理；平台撤权只能停止后续转发。
- 群成员级 DENY 能阻止平台直接转发该成员消息，但不能从其他群友的自然语言引用中完全清除间接信息。
- AI 输出不可信。任何 Tool、主动发送和高风险动作都必须走结构化协议、平台鉴权、必要审批和审计。
- 当前未做真实 GeWe、MaiBot、模型 Provider、生产 PostgreSQL 和公网环境联调，因此项目仍是“本地开发版本”，不是“可直接生产上线版本”。
